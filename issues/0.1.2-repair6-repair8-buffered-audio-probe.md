# Repair6-Repair8 — Audio publication boundary (experimental)

Prior repairs showed that function calls can appear after partial model speech. Muting only when the call arrives leaks acknowledgements. Both Mini and Full dry-run selection produced pre-tool text; neither avoided it.

Experiment: capture WebRTC output into a private muted MediaRecorder stream, inspect the complete response for function calls, and release only an approved direct answer or simulated post-tool result. This deliberately adds full-answer waiting time. Core tool execution and Luna remain disabled in this mode; no changes to default routing mode. Rollback: run `mini` or `mini-fast` launchers without applying another patch.

V1 comparison: preserve explicit provider-event lifecycle, read-only tool selection, and deterministic action authority rather than trusting a model-generated acknowledgement. Neither V1 nor Realtime's server events prove it is safe to release arbitrary partial speech before the tool decision.

Live validation required: audio first syllable, MediaRecorder compatibility, buffer completion, interruption, and timing on Windows/Electron. Static tests alone do not establish correct WebRTC media behavior.
