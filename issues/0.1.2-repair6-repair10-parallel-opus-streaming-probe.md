# Repair6-Repair10 — Experimental parallel authority + continuously streamed private audio

**Status:** Developer-only, unaccepted until Windows live test. Do not replace production safe routing or `mini-fast`.

## Why

Repair8/Repair9 held an entire MediaRecorder recording until `response.done`. This safely suppressed pre-tool speech but turned ordinary responses into 3–12 second wait times. The experiment must retain one continuous Realtime voice without splitting into sentence-sized syntheses.

## New opt-in launcher

`python scripts/realtime_ab.py mini-overlap`

The launcher disables the old parallel shadow probe and old buffer probe. Each utterance causes exactly two **out-of-band** Realtime responses: a text-only tool decision and a tool-free audio candidate. Only the decision's `direct` result permits the candidate to play. The candidate's WebRTC media track is permanently muted and privately captured through `MediaRecorder`/`MediaSource` (`audio/webm;codecs=opus`), allowing incremental playback of the **same** voice generation rather than a finished recording.

### Critical safety properties

- Both responses are `conversation:'none'`: no speculative writes to primary conversation history.
- Audio candidate uses `tools:[]` and `tool_choice:'none'`; decision uses text-only and probes `ask_luna`/`test_action`.
- The Core bridge **never receives probe tool calls**. No actual Luna reasoning or external action occurs.
- If a tool is selected, cancel and discard candidate output; present only an accurately labeled text-only dry-run result. There is intentionally **no speech on tool turns yet**.
- The raw WebRTC audio element remains muted. Only the private `MediaSource` player has playback authority after the direct decision.
- Recording cap of 8 MB; no streaming support, API errors, or unexpected completion must fail closed.
- User interruption discards buffered speech and stops the private playback player.
- Normal launch modes are untouched.

## What live testing must verify

1. `mini-overlap` launches and logs `[Jarvis Overlap]` and `[Jarvis Tool Probe]` for direct and tool requests.
2. Direct questions have one complete, continuous Cedar-voice reply with matching captions. No preamble before authorization.
3. Tool requests select `ask_luna`/`test_action`, generate **no audible pre-tool speech**, and state in text that nothing was executed.
4. An interruption immediately stops streaming player and does not leak audio into the next turn.
5. Measure route-decision time, first audible playback time, cost, and errors. Comparing to `mini-fast` ~498ms and Repair9 3–12sec is the purpose of this probe.

## Current limitations

Browser `MediaRecorder` + `MediaSource` WebM/Opus compatibility and two concurrent out-of-band responses require validation on the target Electron runtime. The API documents parallel out-of-band responses, but WebRTC media delivery and codec container handling are implementation-sensitive. This is **not a production guarantee**. If the platform cannot play appended MediaRecorder chunks, prefer an isolated PCM/WebSocket path rather than repeatedly adjusting sentence chunking or prompt instructions.

The default voice remains Mini, Core permissions remain authoritative, and the project version remains 0.1.2 until live acceptance.
