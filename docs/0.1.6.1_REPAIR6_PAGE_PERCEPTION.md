# Jarvis Core v2 — 0.1.6.1 Repair6: grounded page perception (phase 1)

Purpose:
- Read the CURRENT connected browser page on demand for questions about the page or hypothetical scrolling without modifying it. Spoken answers are derived from a fresh active-tab snapshot (URL identity, scroll range and limited page identity); uncertain/unseen content is explicitly qualified.
- Select an active YouTube search video by user-spoken *approximate title* from fresh, safe result labels. Rank candidates conservatively; no guess if ambiguous; navigate via the same guarded same-tab flow used by numbered selection.
- Keep Core transcript-bound permission checking, same-tab URL verification, video-ID validation, no autoplay claims and no duplicate navigation.
- Only read-only inspection results are spoken; visible actions remain silent.

Limitations:
- Title matching uses transparent text overlap/fuzzy ordering, not a broad multimodal semantic model. It may reject paraphrases or uncertain matches. Thumbnail object recognition and real vision are not implemented; Jarvis must not guess what an image contains.
- Page answers use verified URL/page-type metadata, scrolling state and bounded page title, NOT full visual understanding. For unsupported sites, Jarvis should acknowledge unknown unseen contents. These are initial general browser-perception primitives, not complete computer vision.
- Additional model routing and Windows interaction tests are still required; offline tests do not prove Mini chooses the correct tool. This patch has no browser extension changes, no history schema changes and no new costs for ordinary non-browser conversation.

Install in the Jarvis project root; never force a conflicting merge. The live Windows user project is authoritative. Do not commit until all live tests pass.
