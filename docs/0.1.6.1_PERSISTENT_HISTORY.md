# Jarvis Core v2 — 0.1.6.1 Persistent Conversation History

This first slice of Memory 2.0 creates a **local, Core-owned, durable conversation archive**. It is not yet automatic memory extraction or retrieval injection, and no History/Memory settings UI has been introduced.

## What is recorded

- New session for each connected Realtime desktop conversation (sleep/wake may create a new session)
- Completed *recognized* user voice transcripts and typed messages
- Completed user-facing reply text reported by the renderer (not internal/speculative routing and cancelled text)
- Core browser action outcome codes after execution, with success/failure status
- Source, role, turn ID, timestamp, model, owner and device identifiers

Voice transcription may not be a perfectly word-for-word audio record. A response reported at completion might be interrupted before all its audio is actually heard. This phase intentionally marks those as `reported_output`, **not verified audio playback**. We do not record raw microphone audio, screen images, browser page contents, passwords separately, or hidden model reasoning. An unexpected host crash may leave a session without `ended_at`.

## Location and privacy

- Default database: `.runtime/memory/chat_history.sqlite3` (inside the local project, ignored by Git)
- SQLite WAL transactions, SQLite FTS5 search when available, no remote database and no extra cloud model calls
- The archive **contains private conversation text**. Device backups and other software with filesystem access may read it. It is *not encrypted at rest* in 0.1.6.1. Protect Windows user accounts and disk; encrypted storage, per-person identity, UI access control and consent controls are planned.
- Storage default is ON for this desktop alpha. Set `JARVIS_CHAT_HISTORY_ENABLED=0` in `.env` for no new history writes (restart Jarvis). Set `JARVIS_CHAT_HISTORY_DB=<path>` for a private local file.
- Do **not** `git add -f` `.runtime/` or share the database in project ZIPs.

## Inspect and search

With Jarvis stopped or running, from project root:

```powershell
python .\scripts\chat_history.py list
```

```powershell
python .\scripts\chat_history.py search "Sidemen"
```

```powershell
python .\scripts\chat_history.py show SESSION_ID
```

Deleting an old conversation requires explicit confirmation and cannot be undone:

```powershell
python .\scripts\chat_history.py delete-session SESSION_ID --yes
```

You can also disable new recording by setting `JARVIS_CHAT_HISTORY_ENABLED=0` in `.env` and restarting Jarvis. Turning off recording does **not** erase existing history.

## Verification / acceptance

1. Run focused test and full Python suite; verify desktop build.
2. Start Jarvis and say each of the five standard conversation phrases (wake, math, planets, capital, sleep).
3. Close/restart Jarvis. `list` should show the session(s), `show` should show user/assistant turns; `search "Mars"` should find the relevant record.
4. Test browser open/search/play/pause/resume and confirm no action-routing regression; action outcomes are logged separately.
5. Test the same spoken word twice in separate turns: both should be present. Check there are no repeated entries from the same event replay.
6. No transcript data belongs in Git; verify `git status` before cleanup/commit.
