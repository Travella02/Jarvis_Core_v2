# 0.1.7.0 — Terra foreground computer navigation (experimental alpha)

This is an opt-in, bounded first integration of `gpt-6.1-terra` in Jarvis Core v2. It is **not** an unattended production computer-use agent. It never supplies application launching. Existing `launch_app` and browser actions are unchanged. Terra accepts a confirmed current-turn navigation task for the already-focused app and can receive a PNG screenshot from the user's desktop.

## Configure

Add to your existing local `.env` (do not commit this file):

```dotenv
JARVIS_TERRA_NAV_ENABLED=1
JARVIS_TERRA_NAV_EXECUTE=0
JARVIS_TERRA_NAV_ALLOW_TYPING=0
JARVIS_TERRA_NAV_APPS=msedge.exe,chrome.exe,firefox.exe,discord.exe,spotify.exe,explorer.exe,notepad.exe
```

Use the same `OPENAI_API_KEY` as before, with API project access to `gpt-6.1-terra`. **ChatGPT subscriptions do not include API usage.** Install the added Pillow and PyAutoGUI requirements from requirements.txt (`python -m pip install -r requirements.txt`). This sends screenshots of the active app to OpenAI. Use only test windows without private data or authenticated sessions.

Start in preview mode (`JARVIS_TERRA_NAV_EXECUTE=0`), where physical input is not performed. After an inspected preview and only on a disposable app/demo browser profile, set `JARVIS_TERRA_NAV_EXECUTE=1`, restart Jarvis, and test. Keep typing disabled until explicitly needed; when enabled, Terra may only type ASCII text literally present in the confirmed user speech. `JARVIS_TERRA_NAV_ENABLED=0` removes the tool from Mini's available choices. For an app not on the approved list, configure its executable name through `JARVIS_TERRA_NAV_APPS`, after reviewing its risk.

## Functionality & boundaries

- Uses a fresh screenshot of the current foreground window, then the official Responses API `computer` tool with the `gpt-6.1-terra` model.
- Exposes a separate Mini tool `navigate_app`, with Core checking the confirmed turn, binding and active app. Existing `launch_app` still handles opening installed apps. Browser search/open remains possible through the existing browser path.
- Allows bounded **left clicks**, **double clicks**, **vertical scroll**, **navigation-only keypresses**, optional explicitly authorized typing, and screenshots. No arbitrary code, command lines, OS app launch, or shell tool access.
- Captures new screenshots after bounded action batches, checks that the focused process and window identity are unchanged, and aborts if they change. Maximum five model decisions, three actions per response, ten non-screenshot actions and 45 seconds. A new turn interrupts further actions at the next check.
- Default app allowlist excludes consoles, installers, system security interfaces, and admin tools.
- The model's final claims are not treated as verified task completion. A successful action receipt means permitted controls were exercised on the target window, not that a business outcome was achieved.
- Screenshots are sent via Responses with `store=false`. This is not the same as guaranteeing zero retention or that data never leaves the computer.
- Multi-monitor/HiDPI layouts require testing. Windows foreground window larger than 2400x1600 is rejected rather than returning mismatched click coordinates; resize it. We cannot test real Windows mouse/screen behavior from this build environment.

**Important safety limit:** As an initial alpha, a low-risk click may still have consequences in a live app, and a screenshot can expose sensitive material. The model prompt alone cannot identify every destructive control. Do not enable execution in banking, shopping, email, admin consoles, logged-in production apps, or sensitive workflows. Future releases should use isolated browser/VM execution, per-action risk inspection/approval, OS-level accessibility tree, and stronger outcome verification before general unattended automation.

## Standard voice regression

1. "Hey Jarvis" → wake confirmation.
2. "What is seventeen times twenty-three?" → 391.
3. "What planet is known as the Red Planet?" → Mars.
4. "What is the capital of France?" → Paris.
5. "Thanks Jarvis, that's all" → sleep.

## Focused acceptance

1. Open a disposable Notepad window **yourself** using the existing `launch_app` path; leave Notepad focused. With Terra enabled and execution off, say "Jarvis, click the File menu in this open Notepad." Expected: no click; Terra returns `preview_only`. If Mini does not select `navigate_app`, inspect `[Jarvis Tool Probe]` and do not mark this a passing case.
2. After switching to execution mode on a disposable Notepad window: "Jarvis, open the File menu in this window." Expected: `navigate_app` routed, Terra clicks File, the menu opens, and an `actions_executed_not_goal_verified` receipt is logged. If a menu isn't visible, mark failure.
3. In a **non-signed-in browser test window** and the browser focused, "Jarvis, select the visible video thumbnail with the person in a red coat." Expected: Terra inspects visible thumbnails and, if unambiguous and actually visible, selects it. Do not claim success if not visible or if more than one match.
4. "Jarvis, scroll down in this app." Expected: scroll in the already-focused app, no new app launched.
5. "Jarvis, what if you clicked the delete button?" Expected: no `navigate_app` execution, no action.
6. "Jarvis, open Discord." Expected: existing `launch_app` route (not Terra). This test is only necessary if Discord is installed.
7. Bring a non-allowlisted app to foreground. Ask for navigation. Expected: `app_not_allowed` and no physical action.

Check that Jarvis's ordinary conversational first-audio path stays fast. Terra tasks may take longer because they require screenshot/model/action loops. The first API request can incur cost even in preview mode.

## APIs

Model: `gpt-6.1-terra`; Responses computer tool. The implementation uses an explicit stateless input/output loop (`store=false`) so initial and subsequent screenshots remain scoped to a single current user navigation command, not persisted as a server-side conversation. The provider-specific computer action format follows https://developers.openai.com/api/docs/guides/tools-computer-use and https://developers.openai.com/api/docs/guides/tools-computer-use-integration .
