# Jarvis Core v2 0.1.7.4 Repair1: No-action inspection and reliable Core voice

## Scope

- The native isolated-browser inspection path recognizes list/checklist markers such as `[ ] Inspect ...` and never inherits execution or typing permissions.
- If an isolated-browser task refers to inspection but is malformed, mixed with an action, or names the wrong target, Core refuses it **before** screenshot, model call, or input.
- If native inspection is explicitly disabled, a verified read-only inspection can still use Terra for observation, with execution forced off; a proposed click is preview-only and never performed.
- A finished speculative audio response is not cancelled again after Mini chooses a tool.
- A late `response_cancel_not_active` protocol error is ignored as a stale cancellation acknowledgment, rather than cancelling the new Core-result speech. All other audio failures remain actionable.
- Conversational hypotheticals about background links are instructed not to claim that a foreground tab must be focused, or to invent a confirmed link or destination.

## Configuration and status

No `.env` changes are required. Keep `JARVIS_TERRA_NAV_EXECUTE=0` until the Windows repair tests pass. Use the existing synthetic `jarvis.invalid` playground for safe testing; never enable unrestricted foreground execution in these tests.
