# 0.1.6.1 Repair5 — Contextual continuation and decision caching

Observed on Windows:
- The user says "keep going" immediately after a verified browser scroll; Mini chooses direct conversation instead of continuing the active task. Core correctly did NOT execute an unproposed action.
- Dynamic Core action receipts were prepended to a long routing instruction. In the supplied logs, most context-bearing decisions had `cached=0` while stable prompt turns often used `cached=2304` tokens. This correlation suggests prompt-cache churn; it is not proof of the sole latency cause.
- Ordinary first-audio latency across 4 measured greeting/question replies was 1089, 1027, 1120 and 1089 ms (average 1081 ms), above the user's preferred 500–800 ms target.

Changes:
- Move short dynamic verified task metadata to the END of the static tool-selection instruction so its shared prefix can be cached.
- Strengthen general task-continuation guidance: short immediate continuation imperatives refer to the verified *active task* (including direction) when context supports it; never permanently equate words with scrolling.
- Keep the one-turn/15-second context lifetime, verified Core-sourced context only, fresh per-action authorization, and all negation/hypothetical checks. No new tools or execution fast paths.
- No changes to memory, extension, speech pipeline, or Core permission logic.
