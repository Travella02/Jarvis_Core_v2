# Jarvis Core v2 — 0.1.7.4: verified isolated background navigation

## Purpose

Validate **actual background link navigation** and a second contextual step without moving the physical cursor, typing globally, activating an app, sharing the user's browser profile, or interfering with a foreground game. This release is still deliberately limited: it is **not** general autonomous background desktop control.

## Changes

- The existing 0.1.7.3 browser-native exact-link path now re-resolves the uniquely named link before navigation and independently verifies the final URL is exactly the expected same-origin HTTPS URL, not a redirect or unrelated page. A successful navigation reports `background_link_navigated` only after that check.
- The Playwright browser context prevents off-host and non-GET/HEAD network requests **before** navigation, including redirects and external subresources. This is a conservative limit and can break legitimate websites. No downloads; popups fail closed.
- Requests resembling background clicks/follows/opens that don't pass the strict quoted-link evidence check cannot fall through to unrestricted Terra clicking. Core keeps the active-turn and no-hypothetical checks.
- Successful invisible navigation is spoken aloud. No page text is logged. All browser state stays in the isolated, reused in-memory session.
- Optional **offline test playground**, with three static pages, exists only when enabled AND the configured browser host is exactly `jarvis.invalid`. All requests are fulfilled by an in-process route; no external network is contacted, no credentials or cookies from your real browser are used, and no real website is manipulated.
- `.env.example` now documents `JARVIS_TERRA_BACKGROUND_TEST_PLAYGROUND`.

## Installation

Apply this ZIP **on top of the committed 0.1.7.3 Repair1** (do not reinstall the older patches). Quit Jarvis, extract into project root, then:

```
python .\apply_0_1_7_4_verified_background_navigation.py
python -m unittest tests.unit.test_0_1_7_4_verified_background_navigation -v
python -m unittest discover -s tests\unit -p "test_*.py" -q
npm run desktop:build
```

## Preview and live navigation: OFFLINE playground

These settings REPLACE the corresponding existing background URL/hosts settings only for the safe test. Keep the other `.env` entries unchanged:

```
JARVIS_TERRA_NAV_ENABLED=1
JARVIS_TERRA_NAV_MODE=isolated_browser
JARVIS_TERRA_NAV_EXECUTE=0
JARVIS_TERRA_NAV_FOREGROUND_INPUT=0
JARVIS_TERRA_NAV_ALLOW_TYPING=0
JARVIS_TERRA_BACKGROUND_NATIVE_INSPECT=1
JARVIS_TERRA_BACKGROUND_DIRECT_LINKS=1
JARVIS_TERRA_BACKGROUND_TEST_PLAYGROUND=1
JARVIS_TERRA_BACKGROUND_URL=https://jarvis.invalid/start
JARVIS_TERRA_BACKGROUND_HOSTS=jarvis.invalid
JARVIS_TERRA_BACKGROUND_IDLE_TTL=120
```

Start Jarvis using the normal `mini-overlap-luna-trim-guided-universal-apps` launcher. Run the five usual conversation tests (Hey Jarvis; 17 × 23 = 391; Red Planet = Mars; France capital = Paris; Thanks Jarvis that's all = sleep). Then **type**:

1. `Inspect the isolated background browser at jarvis.invalid.` Expected: `observed_only`; page title `Jarvis Test Start`; 0 model calls; no foreground changes.
2. `Click the "Chapter One" link in the isolated background browser at jarvis.invalid.` Expected: **`preview_only`**, no navigation because execute is 0.

Only after the preview is correct, set `JARVIS_TERRA_NAV_EXECUTE=1`, restart Jarvis, and test:

3. `Inspect the isolated background browser at jarvis.invalid.` Expected `Jarvis Test Start`.
4. `Click the "Chapter One" link in the isolated background browser at jarvis.invalid.` Expected `background_link_navigated`, log `[Jarvis Background Navigation] status=verified`, audible confirmation. No real mouse/keyboard or foreground focus change.
5. `Inspect the isolated background browser at jarvis.invalid.` Expected `Jarvis Chapter One` — this verifies the **same persistent session** retained the navigation.
6. `Click the "Chapter Two" link in the isolated background browser at jarvis.invalid.` Expected verified navigation.
7. `Inspect the isolated background browser at jarvis.invalid.` Expected `Jarvis Chapter Two`.
8. `Click the "Missing" link in the isolated background browser at jarvis.invalid.` Expected `background_link_unverified`, no navigation.
9. `What if you clicked the "Back to Start" link in the background browser?` Expected no action.
10. `Click the File menu in Notepad.` Expected `background_target_unverified`, no foreground action.
11. `Open Notepad.` Existing application launch route should remain independent; **do not** test while a game is active.

If voice transcribes the link labels inaccurately, repeat the targeted browser test via **typed** text to isolate model routing versus speech recognition. No browser extension reload is needed.

## Real websites

Playground mode must be **OFF** for real approved hosts. Disable execute and direct links again before leaving the test (`JARVIS_TERRA_NAV_EXECUTE=0`, `JARVIS_TERRA_BACKGROUND_DIRECT_LINKS=0`, `JARVIS_TERRA_BACKGROUND_TEST_PLAYGROUND=0`, and restore `https://example.org/` + `example.org`). Do not run native click experiments on authenticated accounts, billing, private data, game clients, or arbitrary websites. A seemingly safe GET link may have server-side effects; exact URL verification is not proof of site safety.

## Limitations

- Exact **quoted** accessible link labels only; no button clicking, form submission, arbitrary external websites, cross-host redirects, or automated multi-site browsing.
- One instruction per turn, reusing the current isolated browser. The context does not yet survive Core restarts.
- Linux/container offline unit mocks pass; real Chromium + Windows UI/model routing remain to be verified. Normal speech latency and safety were not modified.
- Foreground protected-game and user-activity safeguards remain; the isolated browser never injects OS input. These checks do not guarantee compatibility with all anti-cheat software; do not test during protected gameplay.
