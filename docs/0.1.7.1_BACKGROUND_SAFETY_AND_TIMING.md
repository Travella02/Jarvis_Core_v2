# Jarvis Core v2 0.1.7.1 — Fast-path instrumentation and foreground protection

## Scope

This patch **does not** replace `gpt-realtime-2.1-mini`, change Core authority, or change the installed-app discovery/launch system. Terra remains an opt-in, user-requested navigation engine. All existing 0.1.7.0 configuration values still work in preview mode; **foreground physical execution now needs another opt-in**.

- **Per-stage timings**: Each Terra task logs `[Jarvis Terra Timing] setup_ms=... | snapshot_ms=... | model_ms=... | action_ms=... | verify_ms=... | total_ms=... | outcome=...` without user text, screenshots, or key contents. This separates slow model calls from local input latency.
- **Smaller screenshots**: Terra sends a JPEG at quality 78 (rather than full PNG) at the same physical screenshot coordinates, and uses high image detail plus a reduced maximum output token budget. This may reduce payload/transmission and cost, but is NOT a guarantee of lower end-to-end latency or identical perception accuracy.
- **Closed-window report**: If an action closes the original Windows handle, it reports `target_window_closed_unverified` rather than silently labeling a subsequent screenshot failure `terra_api_or_driver_error`. An accepted input or closed window is still **not proof of completed user intent**.
- **Foreground safety**: Full-screen/immersive or configured protected foreground executables block Terra and potentially focus-changing legacy browser/launch routes. Terra foreground physical input also checks whether the user has recently used Windows input. Inactivity is only one signal, NOT anti-cheat certification. No game process access or gameplay automation.
- **Isolated browser**: OPTIONAL Playwright headless Chromium mode; fresh disposable browser context per user task, scoped to an explicitly allowlisted HTTPS origin. No shared login cookies, no real mouse/keyboard, no activation of the user's browser or game. This is the only new background execution environment in this release; **Discord, Spotify, Notepad and general desktop apps are NOT background-automated**. No cross-turn session persistence yet. The task must name the background browser or its configured domain.

## Config A: Safe foreground preview

In existing `.env`, leave other settings alone:

```dotenv
JARVIS_TERRA_NAV_ENABLED=1
JARVIS_TERRA_NAV_MODE=foreground
JARVIS_TERRA_NAV_EXECUTE=0
JARVIS_TERRA_NAV_FOREGROUND_INPUT=0
JARVIS_TERRA_NAV_ALLOW_TYPING=0
```

Open a disposable Notepad window. Say, "Jarvis, click File in this open Notepad." Expect `preview_only` and no click. Notice the new stage timings. Ordinary baseline voice still uses Mini, not Terra.

## Config B: Foreground execution (disposable Notepad only)

After preview passes, explicitly opt in:

```dotenv
JARVIS_TERRA_NAV_MODE=foreground
JARVIS_TERRA_NAV_EXECUTE=1
JARVIS_TERRA_NAV_FOREGROUND_INPUT=1
JARVIS_TERRA_NAV_MIN_IDLE_SECONDS=1.5
JARVIS_TERRA_NAV_ALLOW_TYPING=0
```

Restart Jarvis. Focus an unsaved, disposable Notepad and allow a moment of mouse/keyboard inactivity. Say "Jarvis, click File in this open Notepad." Expected a click if approved; **actions_executed_not_goal_verified** remains possible. If the physical input was recent, `user_currently_active` may refuse, as designed. Never enable this during games or anti-cheat-protected software.

## Config C: Truly isolated background browser

This is NOT the user's current tab. First install optional Playwright and its dedicated Chromium binary (one command at a time):

```powershell
python -m pip install playwright
```

```powershell
python -m playwright install chromium
```

For example, to test only the disposable public site `https://example.org`:

```dotenv
JARVIS_TERRA_NAV_ENABLED=1
JARVIS_TERRA_NAV_MODE=isolated_browser
JARVIS_TERRA_NAV_EXECUTE=0
JARVIS_TERRA_NAV_FOREGROUND_INPUT=0
JARVIS_TERRA_NAV_ALLOW_TYPING=0
JARVIS_TERRA_BACKGROUND_URL=https://example.org/
JARVIS_TERRA_BACKGROUND_HOSTS=example.org
```

Start in preview mode. Try "Jarvis, inspect the background browser." Expect `observed_only` (or a truthful error if the browser dependency/site is unavailable). A command about Notepad must be denied as `background_target_unverified`. To test a low-risk click with `JARVIS_TERRA_NAV_EXECUTE=1`, first use a **separately controlled disposable test site**, never a logged-in production site. This mode cannot bring the user's game into focus. Since a fresh headless context is created for every task, follow-ups do not yet operate a persistent browser state. Cross-origin navigation/popups are denied; avoid authenticated, payment or sensitive workflows.

## Gaming protection

A fullscreen game or detected known protected executable blocks focus-changing app-launch and browser operations. Windowed games and new titles may not be detected. Add your executable to:

```dotenv
JARVIS_PROTECTED_PROCESSES=mygame.exe,othergame.exe
```

This is a best-effort interruption guard, NOT an exhaustive game or anti-cheat detector. Never use Terra's physical input with a game, enable gameplay automation, inject into processes, or attempt anti-cheat bypass. If in doubt, use only isolated-browser mode and test compatibility yourself outside protected gameplay.

## Production limitations and next work

- Background navigation for arbitrary already-open desktop applications is NOT supported. Use app-native APIs, noninvasive accessibility patterns, or truly isolated desktop/VMs after separate safety validation. A virtual desktop alone does not isolate the physical cursor.
- Foreground protection cannot guarantee no focus conflict or anti-cheat issue; user input can race with checks. There is no safe way to use shared OS mouse injection concurrently with active gaming.
- Prompt instructions alone do not reliably determine the consequences of a click. Avoid sensitive workflows.
- No verified Windows/Playwright live integration in this offline environment, and no measured end-to-end speed improvement yet. Decide next optimizations from timing logs.
- Do not commit 0.1.7.1 until tested on Windows. Do not delete `.runtime` or `.env`.
