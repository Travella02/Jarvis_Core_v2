# 0.1.6.1 Repair1 — Browser natural follow-up compatibility

This patch modifies only Core browser proposal reconciliation, model instructions,
and adds regression tests. It does not touch the persistent history store or its database.

## What it fixes

Mini sometimes chooses a generic `open` or `play` instead of `select_result`
for an utterance like "Let's watch the first one". Core now translates that
*existing proposed browser action* into `select_result` **only** if the freshly
confirmed user transcript independently authorizes one numbered result.
The browser bridge still checks the actual active YouTube search-results tab,
fetches a fresh page snapshot, verifies a safe numbered watch link, and navigates
once in the same tab. Nothing is performed if the tab is different or the
extension is missing.

## What it does NOT do

This is NOT arbitrary multi-action sequencing. "Pause that, then resume it"
remains unsupported as a single multi-step operation: rather than execute only
half or pretend browser controls don't exist, Jarvis should ask to pause now
and resume when directed. Test `Pause the video` and `Resume it` separately.

## Windows validation

1. Apply via `python .\apply_0_1_6_1_repair1_browser_context.py`.
2. Run `python -m unittest tests.unit.test_0_1_6_1_repair1_browser_context -v`.
3. Run `python -m unittest discover -s tests\unit -p "test_*.py" -q`.
4. Run `npm run desktop:build`.
5. Launch usual `realtime_ab.py` Mini profile and test natural follow-ups.

Do not commit until all tests pass. Installer saves backups. Do not remove
`.runtime/memory/chat_history.sqlite3`; it holds private chat history.
